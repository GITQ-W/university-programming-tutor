# 代码诊断与验证

## 从错误现象定位根因

先记录题意、有效输入、预期结果、原始报错和构建方式。阅读入口、调用点及相关定义，避免只看报错行。编译器的一次前置错误可能产生多条后续诊断，应合并同一根因。

按实际问题选择检查项，无须把每项都输出：

| 层次 | 重点 |
| --- | --- |
| 构建与语言规则 | 语法、声明与定义、作用域、类型转换、重载、链接、类名和路径、标准或版本不匹配 |
| 数据与生命周期 | 初始化、空值、边界、所有权、悬空引用、整数范围、别名、资源释放 |
| 控制流与算法 | 循环不变量、终止条件、递归基例、状态转移、排序或二分前提、修改中的遍历 |
| 输入输出约定 | 多组输入、EOF、空行、空格、负数、编码、换行、OJ 精确输出 |
| 资源与性能 | 时间和空间复杂度、递归深度、重复复制、数据规模，区分最坏与均摊情况 |

算法错误必须关联题目中的有效输入。题目保证输入有效时，缺少无效输入处理通常是可选健壮性建议。不能将一个 `O(n²)` 算法仅凭形式判为超时；结合 n、限制和操作成本判断。

## 问题如何表述

推荐字段：`位置｜影响等级｜证据｜触发条件与根因｜修复`。

- **阻断**：构建失败或核心入口不可用。
- **高**：有效输入下产生未定义行为、崩溃或核心结果错误。
- **中**：部分边界或特定环境下错误、违反课程约束，或有明确依据的资源问题。
- **建议**：可维护性、可读性、可选优化，不影响已知需求的正确性。

以实际影响调整等级，不把证据较少的问题自动降为风格建议。`静态确定`也可属于高影响；`待验证`必须写明尚缺什么证据。不要给出没有校准依据的置信百分比。

位置优先用实际文件和行号；聊天代码可按原片段编号，并注明“片段行号”。避免因重新排版而报错位置。一个问题可以涉及多处代码，区分根因位置与症状位置。

## 有效的验证

1. 先给出一个尽量小、满足题目约束的反例，独立推导预期输出。
2. 能执行时记录工具版本、命令、输入、退出状态和关键输出。严格区分自己运行的结果和用户提供的日志。
3. 修复后复用同一反例，再挑选与修改相关的情况：空或最小输入（若允许）、单元素、边界值、重复值、顺逆序、负数、连续多次调用等。
4. 对算法可用小规模穷举或简单可信实现做差分检查。先确定参考实现和比较规则正确，再使用随机测试；记录随机种子。浮点容差应来自题目或数值分析，不能任意放宽。
5. 构建失败后不继续运行旧可执行文件。超时、异常和 sanitizer 诊断也属于失败，即使程序曾打印预期输出。

修复应消除根因，不能只让一个样例通过。不要修改测试期望来迁就实现；题意本身有歧义时先分情况说明。只有用户要求全量重构时才扩大改动。

## 编译与运行工具的使用

先使用项目规定的构建和测试方式；检查配置中是否有非必要副作用。下面是独立小程序的命令示意，假设在临时目录、文件名相符，并已选定标准。按操作系统、编译器与课程要求调整。

### C / C++

GCC 常规诊断示例（C17、C++17 是示例标准，不是强制课程标准）：

```text
gcc -std=c17 -Wall -Wextra -Wpedantic -g main.c -o main.exe
g++ -std=c++17 -Wall -Wextra -Wpedantic -g main.cpp -o main.exe
```

需要检查内存与未定义行为，且目标工具链支持时，在单独构建中加入：

```text
-O1 -fsanitize=address,undefined -fno-sanitize-recover=undefined -fno-omit-frame-pointer
```

编译和链接均须保留 sanitizer 所需选项。阅读实际诊断，工具链不支持时如实说明并退回可用检查；不能把参数不受支持解释为学生源码错误。按需使用 `-Wconversion` 等更严格选项，逐条判读，不将每个 warning 当成缺陷。

Sanitizer 只覆盖所启用检查及实际执行路径，不能检查一切未定义行为；无诊断不等于内存或算法完全正确。[GCC 官方插桩选项](https://gcc.gnu.org/onlinedocs/gcc/Instrumentation-Options.html)

### Java

```text
javac -Xlint:all -d build Main.java
java -ea -cp build Main
```

上述命令假设默认包、入口类为 `Main`，`build` 是临时输出目录。包结构、多文件和第三方依赖使用项目构建方式。核对 `javac` 与 `java` 的版本兼容；`-ea` 启用已有断言，本身不生成测试。不能仅因静态检查未报错就认定不会发生空指针或下标异常。

### Python

```text
python -m py_compile main.py
python main.py
```

`py_compile` 用于语法编译检查并写入字节码，不验证算法，也不执行被检查模块的顶层逻辑。实际执行前检查模块顶层、导入链和文件等副作用。优先使用项目解释器和已有测试；只有项目已配置且确有价值时再运行类型检查或 lint，不把风格规则当成运行规则。

## 交付结论

简明说明“修复了什么、为何有效、验证了什么、还有什么依赖假设”。若无执行条件，使用“静态分析发现……；以下是建议验证步骤，尚未运行”，不得写“全部通过”。仅运行 Python 时也不能声称已验证 C、C++ 或 Java。
