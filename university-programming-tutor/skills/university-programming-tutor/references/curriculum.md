# 大学编程知识体系

## 如何组织学习范围

用户给出教材、教学进度或考试范围时，以其为主线。未给出时使用下列大学常见学习路径作为可调整框架，不声称覆盖某校全部考点。不要一次输出四门语言的完整教程。

通用先修关系：

```text
表达式与数据类型 → 分支和循环 → 函数与作用域 → 递归
                      ↓                 ↓
               数组与字符串 → 数据结构与算法 → 复杂度与测试
                                   ↓
                        模块化、资源管理与综合项目
```

面向对象、模板/泛型、异常与文件等主题放在所选语言的合理阶段；不强行套用同一门课的顺序。

## 四门语言的课程主线

| 语言 | 入门基础 | 核心进阶 | 综合与延伸 |
| --- | --- | --- | --- |
| C | 编译与运行、类型与表达式、输入输出、选择循环、函数 | 数组、字符串、指针、作用域与存储期、结构体、递归 | 动态内存、链表、文件、多文件组织、预处理、调试与测试 |
| C++ | 类型与控制流、函数、引用、数组、`string` / `vector` | 类与对象、构造析构、`const`、资源所有权、复制与移动、继承与多态 | 模板、STL 容器与算法、迭代器、异常安全、智能指针、项目组织 |
| Java | JDK 与运行方式、基本类型、控制流、方法、数组、字符串 | 类与封装、继承、接口、多态、异常、包与访问控制 | 集合、泛型、文件与资源、lambda / Stream、测试；并发按课程选学 |
| Python | 环境与运行、对象和类型、分支循环、字符串、列表/元组/字典/集合 | 函数与参数、作用域、可变性与拷贝、推导式、模块、异常、文件 | 类、迭代器/生成器、上下文管理、测试、类型标注、项目环境；数据分析按专业选学 |

算法与数据结构按需要穿插：枚举、查找和排序、二分、递归与分治、栈队列、链表、树与图、哈希、基础贪心和动态规划。先明确输入规模与前提，再比较算法。未在课程范围内的主题标为延伸。

## 输出一个知识点时

每个知识点按适当深度提供：

1. **能做什么**：学生学完应能完成的具体任务。
2. **先修与定义**：依赖哪些概念，关键术语的准确含义。
3. **最小示例与过程**：代码只包含当前概念所需内容，注明语言版本；按需追踪变量或对象。
4. **边界与误区**：给一个有解释价值的反例，说明错误在哪一步发生。
5. **检查理解**：安排输出预测、补全、调错或独立实现，并给出判定标准。

用户仅要提纲时，用“模块｜知识点｜易错点｜典型题型”的紧凑表格。用户要深入讲解时再展开示例，避免把提纲和长篇教程混在一起。

## 学习计划与复习

- 先使用已知基础、目标、可用时间和截止时间；缺失时说明可调整的假设，不要求填完整问卷。
- 每阶段包含可执行产出，例如“独立实现并测试动态数组”，不能只写“掌握指针”。
- 在安排新内容前检查先修薄弱项；用少量诊断题判断，无需先组织整套考试。
- 复习按概念、代码执行、调错、实现和边界验证组合；以实际错题调整难度和顺序。
- 用户要求跨语言学习时围绕同一概念对照，避免四份重复的语法目录。

## 从代码问题回到知识点

用 `错误现象 → 直接根因 → 对应知识点 → 需要补的先修 → 迁移练习` 归纳。

例如，多次调用 Python 函数出现列表内容累积，可沿“默认参数创建时机 → 可变对象与别名 → 每次创建独立对象的需求”讲解，再用二维列表问题检查能否迁移理解。不能看到同类现象就直接套结论，先核对具体源码。
