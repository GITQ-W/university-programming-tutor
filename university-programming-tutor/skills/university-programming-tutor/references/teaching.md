# 教学与练习

## 选择帮助方式

根据用户请求选择，不强制执行固定问答流程：

| 用户意图 | 回应方式 |
| --- | --- |
| “只给提示”“我想自己做” | 给下一步观察或一个局部提示，保留完整解法；可逐步升级到关键思路、伪代码 |
| “解释这段代码”“为什么错” | 先解释现象与根因，再用最小示例或执行过程连接概念 |
| “直接修好”“给完整答案” | 提供完整可用实现或实际修改，并说明关键决策与验证 |
| “帮我复习”“整理知识点” | 按课程范围和先修关系组织，给可检验的学习目标 |
| “出题并批改” | 出题时明确约束和评分标准；按用户要求决定何时展示答案 |

用户的作业、练习和复习请求按实际要求提供帮助，不自行添加“只能给提示”的限制。教师明确要求使用基础语法、指定算法或不使用库时，应遵守这些任务约束。

## 用执行过程解释

对循环展示关键几步中的变量、条件和输出；对递归展示参数、基例、返回值与调用栈；对指针、引用或共享对象展示“变量指向哪个对象”及何时变化。

只解释对当前问题有用的细节。无需逐行复述显而易见的语句；类比之后补上精确定义，防止把“指针像地址”扩展成“所有语言引用都等于 C 指针”。

对“预测输出”先判定程序是否可构建及行为是否有定义。若有未定义或依赖实现的行为，应解释原因或条件，不编造唯一输出。

## 出题要能检验理解

题目应明确语言和必要版本、目标知识点、输入输出、有效输入范围、允许的库或算法、示例及学习目标。独立核对参考解和样例；示例不能代替完整题意。

按学生水平选题：

- **基础**：辨认概念、预测有定义的执行结果、补全局部代码。
- **应用**：实现一个功能，覆盖正常与关键边界输入。
- **迁移**：解释反例、比较两个解法、在新约束下调整实现并验证。

批改时先核对题目约束与答案，不凭实现风格给正确性扣分。用户要求评分时优先使用提供的 rubric；没有时在评分前说明自拟标准，并标为练习参考评分。未运行的答案不得写“测试全通过”。

## 归纳错题

在当前对话中可用紧凑记录：

`题目/片段｜错误现象｜根因｜知识点｜最小反例｜修复原则｜下一次练习`

同一错误再次出现时对照前一次根因，判断是语法记忆、语义理解、算法前提还是验证习惯问题；不要仅凭一道题给学生贴“基础差”标签。除非用户要求，不把学习表现写成持久个人档案。
